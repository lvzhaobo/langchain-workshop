1 图结构基础概念

1.1 节点类型（Node）

🤖
Agent 节点
封装 LLM 调用 + 工具调用
图的核心执行单元
⚙️
工具节点
纯函数节点
确定性操作
API / 数据处理 / IO
🔀
条件判断节点
Router / Condition
根据上游输出路由
不产生新内容
👤
人工介入节点
Human-in-the-Loop
暂停等待审批/输入
再继续执行
📊
汇总/合并节点
Aggregator
等待多上游分支
全部到达后合并

1.2 边类型（Edge）

→

直接边 Direct Edge

无条件路由，上游完成即进入下游：A → B

⇢

条件边 Conditional Edge

根据上游输出动态选择下游：A → 如果 X 则 B，否则 C

⋉

动态边 Dynamic Edge

运行时决定目标节点，常用于不确定数量的并行分支

⇉

扇出/扇入 Fan-out/Fan-in

一对多分发（Fan-out）、多对一汇聚（Fan-in）

1.3 状态设计（State）

概念说明
State Schema定义图中流转的数据结构，所有节点共享读写
状态不可变性每个节点返回新状态而非修改旧状态，便于回滚和审计
局部状态 vs 全局状态哪些字段全图可见、哪些仅父子节点间传递
状态归约器 Reducer多路并行输出如何合并回主状态（追加/覆盖/自定义合并逻辑）

4 多 Agent 协同模式（文档第4章）

以下是文档中明确定义的五种协同模式，均可在 DAG 图上表达。

4.1 Supervisor / Orchestrator 中心化

一个主控 Agent 根据任务类型将子任务路由到不同 Worker，结果汇聚回 Supervisor。

[Supervisor] ├─→ [Worker A] ├─→ [Worker B] └─→ [Worker C] │ [Supervisor] ← 结果归约

适用：任务类型多样、需要中心化决策

4.2 顺序流水线 链式

每个节点的输出是下一个节点的输入，图退化为链（最简单的 DAG 特例）。

[采集] → [清洗] → [分析] → [输出]

适用：明确的多阶段处理流程

4.3 Map-Reduce 并行

Map 阶段：一个任务拆为 N 个子任务，N 个 Worker 并行；Reduce 阶段：Aggregator 汇总。

┌→ [Worker 1] ─┐ [入口] ─┼→ [Worker 2] ─┼→ [聚合器] └→ [Worker 3] ─┘

适用：批量同类任务、文献综述、多路代码审查

4.4 辩论/多路采样 对抗

多 Agent 独立回答同一问题 → 裁判 Agent 综合评判选出最优解。

┌→ [回答者A] ─┐ [入口] ─┼→ [回答者B] ─┼→ [裁判] └→ [回答者C] ─┘

适用：需多角度验证的高风险决策、代码方案选型

4.5 分层/嵌套 Agent 递归

Agent 内部调用另一个子图（Subgraph），形成递归嵌套结构。一个复合节点展开后是另一个完整 DAG。

[父 Agent] │ ├── [子图 A: 完整 DAG] │ ├→ [A1] → [A2] │ └→ [A3] → [A4] │ └── [子图 B: 完整 DAG] ├→ [B1] → [B2] └→ [B3]

适用：复杂任务的模块化拆解，每层有独立的状态空间

7 DAG 设计与执行控制（文档第2章）

2.1 图结构设计

  • DAG 约束：不允许循环依赖，保证执行必然终止
  • 拓扑分层：同层节点可并行，层间串行
  • 依赖声明式：声明依赖关系，引擎自动推导并行度
  • 图即文档：DAG 本身是可读的业务流程描述

2.2 执行控制

  • 拓扑排序驱动：自动计算执行顺序，最大化并行度
  • 条件路由：动态决定下一个节点
  • 检查点 Checkpoint：每步自动保存状态快照
  • 断点续跑：从任意历史 Checkpoint 重新执行
  • 超时与取消：单节点超时 + 全图取消传播

2.3 并行执行模型

  • 数据并行：同一节点多实例处理不同数据分片
  • 任务并行：无依赖关系的节点并行执行
  • 流水线并行：上游部分结果即触发下游
8 Subagent 调用模式（文档第3章）

3.1 调用方式

同步调用父 Agent 阻塞等待完成
异步调用派发后继续，回调/轮询获取
流式调用逐 token/步骤回传中间结果
批量调用N 个同质 Subagent 并行

3.2 上下文传递策略

全量传递复制全部状态（Token 开销大）
子集传递仅最小上下文（高效）
环境继承继承工具集、权限、记忆
结果归约仅返回结构化结果

3.3 隔离与安全

共享内存模式直接读写父状态空间
沙箱模式独立上下文，仅 I/O 交互
权限衰减Subagent 权限 ≤ 父 Agent
9 工程化关注点（文档第7章）
关注点核心内容
可观测性 节点级追踪（输入/输出/耗时/Token 消耗）；图可视化（执行路径高亮、瓶颈着色）；延迟分析
容错与鲁棒性 单节点失败策略（重试 N 次 / 跳过 / 降级 / 转人工）；级联失败隔离；部分成功处理
状态持久化 Checkpoint 自动保存；增量存储（仅保存 diff）；跨会话恢复
流式输出 逐节点流式；跨节点流式（上游边产出边流向下游）；混合模式
测试与评估 节点级单元测试；图级集成测试；基于 Checkpoint 的回归测试；图中嵌入评估节点
10 完整开发流程（文档第8.7节）
1. 画图（白板/纸上先画 DAG 拓扑） 2. 定义 State（TypedDict，确定流转什么数据） 3. 实现节点（Agent/函数，输入 state 返回 dict） 4. 连接边（add_edge / add_conditional_edges） 5. 编译运行（compile + invoke） 6. 加 Checkpoint（需要持久化/中断恢复时） 7. 迭代优化（加节点、改路由、调整并行度）
