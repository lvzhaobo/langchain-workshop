
# Agent记忆分层与画像系统

构建短期、长期、工作区三层记忆持久化机制，同时完成实体识别与用户/人物画像的提取与动态更新。

---

# 一、记忆分层基础概念

## 1.1 为什么需要分层记忆？

LLM Agent 面临的核心矛盾：**上下文窗口有限（128K-1M tokens），但需要跨会话、跨任务持续积累知识**。就像操作系统用虚拟内存在 RAM 和磁盘之间交换数据来制造"无限内存"的幻觉，Agent 记忆系统需要在 LLM 上下文窗口和持久存储之间调度信息。

**三层类比**：

| 记忆层 | 人脑类比 | OS 类比 | 生命周期 |
|--------|---------|---------|---------|
| **短期/工作记忆** | 前额叶皮层（当前思考） | RAM | 单次会话内 |
| **情节记忆** | 海马体（今日经历） | 磁盘缓存（热数据） | 数天~数周 |
| **长期记忆** | 大脑皮层（固化知识） | 冷存储（持久化） | 跨会话永久 |

## 1.2 三层模型详解

### 短期记忆（Working Memory）

```
┌─────────────────────────────────────────────────┐
│              LLM Context Window                  │
│  ┌──────────┐  ┌───────────┐  ┌─────────────┐  │
│  │ System   │  │ Current   │  │ Tool Call   │  │
│  │ Prompt   │  │ Turns     │  │ Results     │  │
│  └──────────┘  └───────────┘  └─────────────┘  │
│  ┌──────────────────────────────────────────┐   │
│  │ Memory Blocks（始终在上下文中的结构块）     │   │
│  │  - persona: Agent 的身份与行为指令         │   │
│  │  - human: Agent 对用户的认知               │   │
│  │  - tasks: 当前跟踪的任务列表               │   │
│  └──────────────────────────────────────────┘   │
└─────────────────────────────────────────────────┘
```

- **内容**：当前对话 Turn、活跃的工具调用结果、Memory Blocks
- **管理策略**：上下文窗口接近上限时触发压缩（Compaction），将旧对话总结后移入情节记忆
- **关键机制**：**预压缩刷新（Pre-compaction Flush）**——压缩前先触发 Agent 将关键信息写入持久存储，防止信息丢失

### 情节记忆（Episodic Memory）

```
┌─────────────────────────────────────────────────┐
│              情节记忆（每日笔记）                  │
│  memory/                                         │
│  ├── 2026-06-19.md    # 昨天的完整会话记录        │
│  ├── 2026-06-20.md    # 今天的实时记录             │
│  └── index.sqlite     # 混合向量+全文索引         │
│                                                   │
│  自动加载策略：                                    │
│  - 今天 + 昨天的笔记自动注入每次会话               │
│  - 更早的笔记通过搜索结果按需加载                  │
└─────────────────────────────────────────────────┘
```

- **内容**：每日会话摘要、关键决策、观察发现、未完成任务
- **索引方式**：向量语义搜索（70% 权重）+ BM25 关键词搜索（30% 权重）
- **加载策略**：近热远冷——今天的全量加载，历史的按需检索

### 长期记忆（Long-Term / Semantic Memory）

```
┌─────────────────────────────────────────────────┐
│              长期记忆                             │
│  MEMORY.md  ← 经过巩固的持久事实（~20K 字符）      │
│                                                   │
│  存储格式（每条一个 Markdown 段落）：              │
│  - 用户偏好：语言偏好、代码风格、沟通频率          │
│  - 事实知识：项目结构、技术栈、关键决策            │
│  - 行为模式：常用命令、典型工作流                  │
│                                                   │
│  写入门控（必须同时满足）：                        │
│  - minScore: 质量评分 >= 阈值                     │
│  - minRecallCount: 被回忆 >= N 次                │
│  - minUniqueQueries: 来自 >= N 个不同查询         │
└─────────────────────────────────────────────────┘
```

- **内容**：经过巩固管道提炼的持久事实、用户偏好、知识条目
- **写入策略**：不是每次对话都直接写入，而是通过**巩固管道**（Dreaming/Consolidation）提升
- **时间衰减**：`score = e^(-λ × days_old)`，30 天半衰期，确保新鲜事实优先

# 二、OpenClaw 记忆设计深度借鉴

OpenClaw (`github.com/openclaw/openclaw`) 是目前最成熟的**文件原生** Agent 记忆系统。其核心理念：

## 2.1 设计哲学

| 原则 | 含义 |
|------|------|
| **Files are the library, vectors are the librarian** | 文件系统是知识的唯一权威来源，向量索引只是检索工具 |
| **Write before you forget** | 在上下文压缩前保存，而不是之后补救 |
| **Memory IS trust infrastructure** | 不能记住自己说过什么的 Agent 不可信 |
| **Single source of truth** | 每一条状态只有一个权威文件 |
| **Nothing is ever deleted** | 旧事实标记为 `historical`，保留 `supersedes` 链 |

## 2.2 文件结构

```
~/.openclaw/workspace/
├── SOUL.md              # Agent 核心哲学与行为准则
├── IDENTITY.md          # 表面身份（名称、语气、代词）
├── USER.md              # 用户画像
├── MEMORY.md            # 长期记忆（~20K 字符软上限）
├── AGENTS.md            # 多 Agent 协作规则
├── BOOTSTRAP.md         # 会话恢复引导
├── HEARTBEAT.md         # 定期自我检查
├── DREAMS.md            # 记忆巩固产物
└── memory/
    ├── 2026-06-19.md    # 每日笔记
    ├── 2026-06-20.md
    └── index.sqlite     # sqlite-vec + FTS5 混合索引
```

## 2.3 巩固管道（Dreaming System）

```
┌──────────┐    ┌──────────┐    ┌──────────┐
│ 轻睡眠    │ → │ REM 睡眠  │ → │ 深睡眠    │
│ Light    │    │ REM      │    │ Deep     │
│ Sleep    │    │ Sleep    │    │ Sleep    │
├──────────┤    ├──────────┤    ├──────────┤
│ 摄入并暂存│    │ 反思并提取│    │ 提升到     │
│ 短期记忆  │    │ 模式      │    │ MEMORY.md │
└──────────┘    └──────────┘    └──────────┘
                                    │
                    三个门控阈值 ─────┘
                    minScore + minRecallCount + minUniqueQueries
```

## 2.4 混合搜索管道

```
Markdown 文件 (*.md)
       │
       ▼
  按行范围分块（Chunking）
       │
       ├──→ 向量嵌入生成 ──→ sqlite-vec 索引（语义搜索 70%）
       │
       └──→ 全文分词 ──→ SQLite FTS5 索引（关键词搜索 30%）
                         │
                         ▼
                    混合搜索结果（加权融合）
                         │
                         ▼
              优雅降级：如果 sqlite-vec 不可用
              → 回退到 JS 暴力余弦相似度计算
```

## 2.5 插件槽架构——可替换记忆后端

OpenClaw 的整个记忆系统通过 `plugins.slots.memory` 可替换：

| 插件 | 存储后端 | 特点 |
|------|---------|------|
| `memory-core`（默认） | Markdown + SQLite | 零依赖、文件原生 |
| `memory-lancedb` | LanceDB 向量数据库 | 自动召回、自动捕获 |
| `memory-wiki` | 结构化 Markdown | 声明/证据/矛盾追踪 |
| `@mem0/openclaw-mem0` | Mem0 提取管道 | 事实去重和动态更新 |
| `openclaw-honcho` | Honcho 服务 | AI 原生跨会话记忆 |
| `claw-mem` | 三层 STM/LTM/Archive | 写入时门控 |

# 三、记忆持久化机制深入

## 3.1 事实提取管道

```
原始对话消息
      │
      ▼
┌──────────────┐
│ 1. 分块       │  按语义边界切分对话片段
└──────┬───────┘
       ▼
┌──────────────┐
│ 2. LLM 提取  │  从每个片段提取候选事实
│              │  prompt: "从以下对话中提取值得记住的事实..."
└──────┬───────┘
       ▼
┌──────────────┐
│ 3. 去重       │  Jaccard 相似度 ≥ 70% 视为重复
│              │  新事实 → 存储；重复事实 → 更新 recall_count
└──────┬───────┘
       ▼
┌──────────────┐
│ 4. 冲突检测   │  与已有事实对比
│              │  - 无冲突 → 存储
│              │  - 有冲突 → 标记旧事实 superseded_by=new_id
└──────┬───────┘
       ▼
┌──────────────┐
│ 5. 门控写入   │  检查三个阈值
│              │  score >= minScore
│              │  recall_count >= minRecallCount
│              │  unique_queries >= minUniqueQueries
└──────────────┘
```

## 3.2 时间衰减评分

```
score = base_score × e^(-λ × days_old)

其中：
  base_score  = 提取时 LLM 给出的初始质量评分 (1-10)
  λ           = ln(2) / half_life_days（如 30 天半衰期，λ ≈ 0.0231）
  days_old    = 当前日期 - 事实创建日期
```

**效果**：
- 创建时 score=10 → 30天后 score≈5 → 60天后 score≈2.5
- 被频繁回忆的事实通过 `recall_count` 和 `unique_queries` 对抗衰减
- 搜索排序时 score 越高的越靠前

## 3.3 上下文压缩策略

```
当前上下文窗口使用率
      │
      ├─ < 70% → 不做处理
      │
      ├─ 70%~90% → 预压缩刷新（Pre-compaction Flush）
      │            Agent 被静默提示：将关键信息写入 MEMORY.md / 今日笔记
      │
      └─ > 90% → 上下文压缩（Compaction）
                  1. 保留最近 N 轮完整对话
                  2. 中间的 tool call/result 对保持原样
                  3. 更早的对话总结为结构化摘要
                  4. 摘要注入系统提示（加 [COMPACTED] 标记）
```

## 3.4 跨会话恢复

```
会话开始时的记忆加载顺序：

1. 加载系统提示（SOUL.md + IDENTITY.md）
2. 加载 MEMORY.md（长期记忆）
3. 加载今日笔记 memory/2026-06-20.md
4. 加载昨日笔记 memory/2026-06-19.md
5. 检查 HEARTBEAT.md（是否有遗留待办）
6. 执行 BOOTSTRAP.md 的恢复引导
7. 开始接收用户输入

会话中按需加载：
  - Agent 调用 memory_search(query) → 混合搜索 → 返回相关片段
  - Agent 调用 memory_get("2026-06-15") → 加载指定日期的笔记
```

# 四、实体识别与用户画像

## 4.1 实体识别（NER）

从对话中自动提取并维护四类实体：

| 实体类型 | 示例 | 识别方式 |
|---------|------|---------|
| **人物** | 用户、用户提到的第三方、Agent 自己 | LLM 提取 + 代词消解 |
| **项目** | 代码仓库、产品名称 | 规则匹配 + LLM 确认 |
| **技术** | 编程语言、框架、工具、API | 规则匹配 + 知识库对照 |
| **概念** | 业务术语、领域知识 | LLM 提取 + 上下文聚类 |

**实体存储格式**：

```yaml
# memory/entities/user.yaml
id: user_main
type: person
name: "张三"
traits:
  role: "后端工程师"
  skill_level: "senior"
  communication_style: "直接"
  preferred_language: "TypeScript"
  active_hours: "9:00-18:00 CST"
  code_review_focus: ["安全性", "性能"]
facts:
  - fact: "使用 PostgreSQL 作为主数据库"
    confidence: 0.95
    created: "2026-06-15"
    last_verified: "2026-06-18"
  - fact: "偏好函数式编程风格"
    confidence: 0.72
    created: "2026-06-16"
    last_verified: "2026-06-16"
```

## 4.2 用户画像维度

参考行为基因组（Behavioral Genome）+ OCEAN 五大人格模型：

```
用户画像 = {
  "身份信息": {
    "角色": "后端工程师",
    "技能水平": "高级",
    "技术栈": ["Python", "TypeScript", "PostgreSQL", "Docker"]
  },
  "行为特征": {
    "观察力": 0.8,       # 是否关注细节
    "果断性": 0.65,       # 快速决策 vs 深思熟虑
    "沟通温度": 0.5,      # 正式 vs 随意
    "幽默度": 0.3,        # 对幽默的接受程度
  },
  "工作偏好": {
    "代码风格": "函数式",
    "注释密度": "中等",
    "测试策略": "先写测试",
    "审查优先级": ["安全 > 性能 > 风格"],
    "活跃时段": "0900-1800 CST",
    "响应期望": "30分钟内"
  },
  "信任建立": {
    "自主决策阈值": 0.7,  # 低于此值需要确认
    "已验证能力": ["代码生成", "API 设计", "Bug 分析"],
    "需提升领域": ["前端布局", "性能 profiling"]
  }
}
```

## 4.3 画像动态更新机制

```
对话事件 → 检测到画像相关信息 → 提取画像更新 → 置信度评估 → 应用更新

更新规则：
1. 新事实 confidence < 0.5 → 暂存为候选，等待更多证据
2. 新事实 confidence >= 0.7 → 直接更新画像
3. 新事实与已有事实冲突 → 触发画像协商（Profile Negotiation）
   - 询问用户"我之前认为你偏好 X，现在看起来是 Y，对吗？"
   - 或根据新近度自动更新（配置选项）
4. 已有事实超过 90 天未验证 → 标记 confidence -= 0.1
```

## 5.3 LoCoMo 基准测试排名

长期对话记忆检索（Long Conversation Memory Benchmark）：

| 系统 | 单跳 | 多跳 | 时间推理 | 综合 |
|------|------|------|---------|------|
| Backboard | 89.4 | 75.0 | 91.9 | **90.0** |
| Zep | 74.1 | 66.0 | 79.8 | 75.1 |
| Letta (文件系统) | - | - | - | 74.0 |

# 七、全链路统一到 LangGraph

## 7.1 为什么 LangGraph 可以统一所有模块

将全部 6 个模块统一到 LangGraph 是可行的，而且 LangGraph 的原语恰好能覆盖每个模块的核心需求：

```
模块1 SDD                 模块2 Harness               模块3 模型调优
┌──────────────────┐    ┌──────────────────┐    ┌──────────────────┐
│ LangGraph 编排    │    │ Harness 驾驭      │    │ 框架无关          │
│ spec→code 流程   │    │ LangGraph Agent   │    │ 微调/提示词/采样  │
│ 作为图上的节点    │    │ 作为可编排单元      │    │ 作为节点策略      │
└──────────────────┘    └──────────────────┘    └──────────────────┘
         │                       │                       │
         └───────────────────────┼───────────────────────┘
                                 │
         ┌───────────────────────┼───────────────────────┐
         │                       │                       │
模块4 基于图的Agent        模块5 记忆分层              模块6 多Agent编排
┌──────────────────┐    ┌──────────────────┐    ┌──────────────────┐
│ StateGraph        │    │ Store (长期)     │    │ Supervisor       │
│ Node + Edge       │    │ Checkpointer     │    │ Swarm / Handoff  │
│ Conditional Edge  │    │ (短期+情节)       │    │ Subgraph         │
│ DAG 编排          │    │ Middleware (画像) │    │ Map-Reduce       │
└──────────────────┘    └──────────────────┘    └──────────────────┘
```

| 模块 | LangGraph 提供的原语 | 覆盖程度 |
|------|---------------------|---------|
| **1-SDD** | 用 StateGraph 编排 spec→code 工作流 | ✅ 完全覆盖 |
| **2-Harness** | Harness 驾驭 LangGraph Agent 的生命周期 | 🔶 Harness 独立，Agent 是 LangGraph |
| **3-模型调优** | 框架无关，调优后的模型作为节点内的 LLM 调用 | 🔶 框架无关 |
| **4-基于图的Agent** | StateGraph + Node + Edge + Conditional Edge | ✅ 完全覆盖（已有 Workshop） |
| **5-记忆分层** | **Store** 做长期记忆 + **Checkpointer** 做短期持久化 | ✅ 完全覆盖 |

### memory_store.py — 基于 LangGraph Store 的长期记忆

```python
"""
基于 LangGraph Store 的长期记忆实现

Store API:
- put(namespace, key, value): 写入
- search(namespace, query, limit): 语义搜索（内置 embedding）
- get(namespace, key): 精确获取
- delete(namespace, key): 删除

命名空间设计（参考 OpenClaw 的文件组织逻辑）：
- ("memories", "{user_id}")              → 用户级长期记忆事实
- ("profiles", "{user_id}")             → 用户画像
- ("sessions", "{user_id}", "{date}")   → 每日会话摘要（情节记忆）
- ("entities", "{entity_type}")         → 实体目录
- ("agent", "persona")                  → Agent 自身身份记忆
"""

from typing import Optional
from datetime import date, datetime
from langgraph.store.base import BaseStore


# ═══════════════════════════════════════════════════════════
# Store 包装器：将三层记忆操作封装为简洁 API
# ═══════════════════════════════════════════════════════════

class MemoryStoreManager:
    """
    LangGraph Store 的记忆管理封装
    
    使用方式：
        store = AsyncPostgresStore.from_conn_string(...)
        memory = MemoryStoreManager(store)
        
        # 写入记忆
        await memory.remember(user_id, "用户偏好 TypeScript", category="preference", score=8)
        
        # 搜索记忆
        results = await memory.recall(user_id, "TypeScript 配置", limit=5)
        
        # 更新画像
        await memory.update_profile(user_id, {"preferred_language": "TypeScript"})
    """

    def __init__(self, store: BaseStore, user_id: str = "default"):
        self.store = store
        self.user_id = user_id

    # ── 长期记忆 CRUD ─────────────────────────────────────

    async def remember(
        self,
        content: str,
        category: str = "knowledge",
        score: float = 5.0,
        confidence: float = 0.5,
        user_id: Optional[str] = None,
    ) -> str:
        """
        写入一条长期记忆

        返回 fact_id
        """
        import hashlib
        uid = user_id or self.user_id
        fact_id = hashlib.md5(f"{uid}:{content}".encode()).hexdigest()[:16]
        namespace = ("memories", uid)

        # 检查是否已有相似事实
        existing = await self.store.search(
            namespace,
            query=content[:200],
            limit=3,
        )
        for item in existing:
            existing_content = item.value.get("content", "")
            similarity = self._jaccard_similarity(content, existing_content)
            if similarity >= 0.7:
                # 更新已有事实的 recall_count
                old_val = item.value
                old_val["recall_count"] = old_val.get("recall_count", 0) + 1
                old_val["last_recalled_at"] = datetime.now().isoformat()
                old_val["confidence"] = max(old_val.get("confidence", 0.5), confidence)
                await self.store.put(namespace, item.key, old_val)
                return item.key

        # 新事实
        fact = {
            "fact_id": fact_id,
            "content": content,
            "category": category,
            "score": score,
            "confidence": confidence,
            "recall_count": 0,
            "created_at": datetime.now().isoformat(),
            "last_recalled_at": None,
            "superseded_by": None,
        }
        await self.store.put(namespace, fact_id, fact)
        return fact_id

    async def recall(
        self,
        query: str,
        limit: int = 5,
        user_id: Optional[str] = None,
        min_score: float = 1.0,
    ) -> list[dict]:
        """
        语义搜索长期记忆
        
        LangGraph Store 的 search() 已内置 embedding 搜索
        """
        uid = user_id or self.user_id
        namespace = ("memories", uid)

        results = await self.store.search(
            namespace,
            query=query,
            limit=limit * 2,  # 多取一些用于后过滤
        )

        # 后过滤 + 排序
        scored = []
        for item in results:
            val = item.value
            if val.get("score", 5) < min_score:
                continue
            
            # 时间衰减
            effective_score = self._decayed_score(val)
            # 被频繁回忆的加权
            recall_bonus = val.get("recall_count", 0) * 0.1
            final_score = effective_score * (1 + recall_bonus)

            scored.append({
                **val,
                "effective_score": final_score,
            })

        scored.sort(key=lambda x: x["effective_score"], reverse=True)
        return scored[:limit]

    async def forget(self, fact_id: str, user_id: Optional[str] = None):
        """标记事实为被替代（而非物理删除）"""
        uid = user_id or self.user_id
        namespace = ("memories", uid)
        existing = await self.store.get(namespace, fact_id)
        if existing:
            val = existing.value
            val["superseded_by"] = "manual_forget"
            await self.store.put(namespace, fact_id, val)

    # ── 情节记忆（会话摘要） ──────────────────────────────

    async def save_session_summary(
        self,
        summary: str,
        session_id: str,
        user_id: Optional[str] = None,
    ):
        """保存会话摘要到情节记忆"""
        uid = user_id or self.user_id
        today = date.today().isoformat()
        namespace = ("sessions", uid, today)

        await self.store.put(
            namespace,
            session_id,
            {
                "summary": summary,
                "session_id": session_id,
                "saved_at": datetime.now().isoformat(),
            },
        )

    async def get_recent_sessions(
        self,
        days: int = 7,
        user_id: Optional[str] = None,
    ) -> list[dict]:
        """获取最近 N 天的会话摘要"""
        uid = user_id or self.user_id
        summaries = []

        for i in range(days):
            d = (date.today() - __import__("datetime").timedelta(days=i)).isoformat()
            namespace = ("sessions", uid, d)
            # 搜索该日期的所有会话
            results = await self.store.search(
                namespace,
                query="session summary",  # 宽泛匹配
                limit=20,
            )
            for item in results:
                summaries.append(item.value)

        return summaries

    # ── 画像管理 ──────────────────────────────────────────

    async def get_profile(self, user_id: Optional[str] = None) -> dict:
        """获取用户画像"""
        uid = user_id or self.user_id
        namespace = ("profiles", uid)
        result = await self.store.get(namespace, "profile")
        if result:
            return result.value
        return {
            "user_id": uid,
            "name": "",
            "role": "",
            "traits": {},
            "facts": [],
            "interaction_count": 0,
        }

    async def update_profile(
        self,
        trait_updates: dict,
        confidence: float = 0.5,
        user_id: Optional[str] = None,
    ):
        """更新用户画像特征（EMA 平滑）"""
        uid = user_id or self.user_id
        namespace = ("profiles", uid)
        profile = await self.get_profile(uid)

        for trait, value in trait_updates.items():
            if trait in profile["traits"]:
                old = profile["traits"][trait]
                alpha = 0.3
                profile["traits"][trait] = {
                    "value": value,
                    "confidence": old["confidence"] * (1 - alpha) + confidence * alpha,
                    "updated_at": datetime.now().isoformat(),
                }
            else:
                profile["traits"][trait] = {
                    "value": value,
                    "confidence": confidence,
                    "first_seen": datetime.now().isoformat(),
                    "updated_at": datetime.now().isoformat(),
                }

        profile["interaction_count"] += 1
        profile["last_seen"] = datetime.now().isoformat()
        await self.store.put(namespace, "profile", profile)

    # ── Agent 自身记忆（参考 OpenClaw 的 SOUL/IDENTITY） ──

    async def set_agent_memory(self, key: str, value: dict):
        """设置 Agent 自身的持久记忆（如 persona、rules）"""
        namespace = ("agent", key)
        await self.store.put(namespace, "current", value)

    async def get_agent_memory(self, key: str) -> Optional[dict]:
        """获取 Agent 自身的持久记忆"""
        namespace = ("agent", key)
        result = await self.store.get(namespace, "current")
        return result.value if result else None

    # ── 工具方法 ──────────────────────────────────────────

    def _decayed_score(self, fact: dict, half_life_days: int = 30) -> float:
        """计算时间衰减后的评分"""
        import math
        created_str = fact.get("created_at", "")
        if not created_str:
            return fact.get("score", 5.0)
        try:
            created = datetime.fromisoformat(created_str).date()
            days = (date.today() - created).days
            lam = math.log(2) / half_life_days
            return fact.get("score", 5.0) * math.exp(-lam * days)
        except (ValueError, TypeError):
            return fact.get("score", 5.0)

    @staticmethod
    def _jaccard_similarity(a: str, b: str) -> float:
        """计算 Jaccard 相似度"""
        set_a = set(a.lower().split())
        set_b = set(b.lower().split())
        if not set_a or not set_b:
            return 0.0
        return len(set_a & set_b) / len(set_a | set_b)
```

### memory_graph.py — 记忆操作封装为 LangGraph 节点

```python
"""
将记忆操作封装为 LangGraph 图的节点

这样做的好处：
1. 记忆读写变成图上的标准节点，受 Checkpointer 保护
2. 可以在任意位置插入记忆节点（before_model / after_model middleware）
3. 与多 Agent 编排天然集成 — 每个 Agent 子图可以有自己的记忆节点
"""

from typing import Literal
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.memory import MemorySaver
from langgraph.store.memory import InMemoryStore
from langchain_core.messages import SystemMessage, HumanMessage, AIMessage

from state import MemoryAgentState
from memory_store import MemoryStoreManager


# ═══════════════════════════════════════════════════════════
# 记忆节点函数（每个节点 = 图上的一个记忆操作步骤）
# ═══════════════════════════════════════════════════════════

async def load_memory_node(state: MemoryAgentState, config: dict) -> dict:
    """
    会话开始时加载相关记忆（类似 OpenClaw 的 start_session）
    
    1. 获取用户画像
    2. 用当前用户消息搜索相关长期记忆
    3. 加载最近的会话摘要
    4. 组装记忆块注入系统提示
    """
    store = config["configurable"]["store"]
    user_id = state["session_meta"].get("user_id", "default")
    memory = MemoryStoreManager(store, user_id)

    # 获取画像
    profile = await memory.get_profile()

    # 用最近一条用户消息搜索记忆
    user_messages = [m for m in state["messages"] if isinstance(m, HumanMessage)]
    query = user_messages[-1].content if user_messages else ""
    recalled = await memory.recall(query, limit=5) if query else []

    # 获取最近会话摘要
    recent_sessions = await memory.get_recent_sessions(days=2)

    # 组装记忆上下文
    memory_context_parts = []

    if recalled:
        memory_context_parts.append("## 相关长期记忆\n")
        for r in recalled:
            memory_context_parts.append(
                f"- [{r['category']}] {r['content']} "
                f"(置信度: {r['confidence']:.2f}, 被回忆: {r['recall_count']}次)"
            )

    if recent_sessions:
        memory_context_parts.append("\n## 最近会话摘要\n")
        for s in recent_sessions[:3]:
            memory_context_parts.append(f"- {s.get('summary', '')[:200]}")

    if profile.get("traits"):
        memory_context_parts.append("\n## 用户画像\n")
        for trait, info in profile["traits"].items():
            memory_context_parts.append(
                f"- {trait}: {info['value']} (置信度: {info['confidence']:.2f})"
            )

    memory_context = "\n".join(memory_context_parts)

    # 将记忆上下文作为 SystemMessage 注入
    system_msg = SystemMessage(content=f"[MEMORY CONTEXT]\n{memory_context}")

    return {
        "memory_context": memory_context,
        "memory_blocks": {
            "profile": profile,
            "recalled": recalled,
            "recent_sessions": recent_sessions,
        },
        "messages": [system_msg],
        "user_profile": profile,
    }


async def save_to_memory_node(state: MemoryAgentState, config: dict) -> dict:
    """
    在 Agent 响应后提取并保存记忆
    
    类似 OpenClaw 的 pre-compaction flush：
    在上下文压缩前将关键信息持久化
    """
    store = config["configurable"]["store"]
    user_id = state["session_meta"].get("user_id", "default")
    memory = MemoryStoreManager(store, user_id)

    # 取最近的几条消息
    recent = state["messages"][-6:]  # 最近 3 轮对话
    text = "\n".join(
        f"{'👤' if isinstance(m, HumanMessage) else '🤖'}: {m.content[:300]}"
        for m in recent
    )

    # TODO: 生产环境用 LLM 提取事实，此处为演示用简化逻辑
    # 实际应调用 LLM: "从以下对话中提取值得记住的事实..."
    facts_to_save = _extract_facts_heuristic(text)

    saved_count = 0
    for fact in facts_to_save:
        await memory.remember(
            content=fact["content"],
            category=fact.get("category", "knowledge"),
            score=fact.get("score", 5.0),
            confidence=fact.get("confidence", 0.5),
        )
        saved_count += 1

    return {
        "pending_consolidation": saved_count > 0,
    }


async def update_profile_node(state: MemoryAgentState, config: dict) -> dict:
    """
    从最新对话中提取画像更新
    
    检查 state.profile_delta，如果有变更则更新到 Store
    """
    delta = state.get("profile_delta")
    if not delta:
        return {}

    store = config["configurable"]["store"]
    user_id = state["session_meta"].get("user_id", "default")
    memory = MemoryStoreManager(store, user_id)

    await memory.update_profile(
        trait_updates=delta.get("traits", {}),
        confidence=delta.get("confidence", 0.5),
    )

    # 同时保存画像相关的事实
    for fact in delta.get("facts", []):
        await memory.remember(
            content=fact,
            category="preference",
            score=7.0,
            confidence=delta.get("confidence", 0.5),
        )

    return {"profile_delta": None}


async def consolidate_memory_node(state: MemoryAgentState, config: dict) -> dict:
    """
    巩固管道（类似 OpenClaw 的 Dreaming）

    触发条件：pending_consolidation == True
    """
    if not state.get("pending_consolidation"):
        return {}

    store = config["configurable"]["store"]
    user_id = state["session_meta"].get("user_id", "default")
    memory = MemoryStoreManager(store, user_id)

    # 获取最近会话
    recent_sessions = await memory.get_recent_sessions(days=7)

    # 合并为文本用于 LLM 分析
    combined = "\n---\n".join(
        s.get("summary", "") for s in recent_sessions
    ) if recent_sessions else ""

    # TODO: 生产环境用 LLM 执行三步巩固
    # 1. 轻睡眠：提取候选事实
    # 2. REM 睡眠：检查冲突
    # 3. 深睡眠：满足门控的提升到长期记忆

    if combined:
        facts = _extract_facts_heuristic(combined)
        for fact in facts:
            if fact.get("score", 5) >= 5.0:  # 门控：评分阈值
                await memory.remember(
                    content=fact["content"],
                    category=fact.get("category", "knowledge"),
                    score=fact.get("score", 5.0),
                    confidence=fact.get("confidence", 0.5),
                )

    return {"pending_consolidation": False}


async def search_memory_node(state: MemoryAgentState, config: dict) -> dict:
    """
    按需搜索记忆（Agent 主动调用时触发）
    
    通常在 Agent 的工具调用中触发此节点
    """
    store = config["configurable"]["store"]
    user_id = state["session_meta"].get("user_id", "default")
    memory = MemoryStoreManager(store, user_id)

    # 用最近的用户消息作为搜索 query
    user_messages = [m for m in state["messages"] if isinstance(m, HumanMessage)]
    query = user_messages[-1].content if user_messages else ""

    if not query:
        return {}

    results = await memory.recall(query, limit=5)

    # 将搜索结果作为上下文注入
    context = "\n".join(
        f"- [{r['category']}] {r['content']} (评分: {r['effective_score']:.1f})"
        for r in results
    ) if results else "（未找到相关记忆）"

    return {
        "memory_context": f"## 按需搜索记忆\n\n查询: {query}\n\n{context}",
    }


# ═══════════════════════════════════════════════════════════
# 辅助函数
# ═══════════════════════════════════════════════════════════

def _extract_facts_heuristic(text: str) -> list[dict]:
    """规则启发式提取事实（生产环境替换为 LLM 提取）"""
    facts = []
    patterns = [
        (["偏好", "喜欢", "习惯", "常用", "倾向于"], "preference", 6.0),
        (["决定", "选择", "采用", "选择"], "decision", 7.0),
        (["是", "使用", "基于", "运行在"], "knowledge", 5.0),
    ]

    for line in text.split("\n"):
        line = line.strip()
        if len(line) < 10:
            continue
        for keywords, category, base_score in patterns:
            if any(kw in line.lower() for kw in keywords):
                import hashlib
                facts.append({
                    "fact_id": hashlib.md5(line.encode()).hexdigest()[:16],
                    "content": line,
                    "category": category,
                    "score": base_score,
                    "confidence": 0.5,
                })
                break

    return facts


# ═══════════════════════════════════════════════════════════
# 编译记忆增强的 Agent 图
# ═══════════════════════════════════════════════════════════

def build_memory_augmented_graph(
    agent_node_func,  # 实际的 Agent 节点（LLM + 工具调用）
    store: InMemoryStore = None,
    checkpointer: MemorySaver = None,
) -> StateGraph:
    """
    构建带三层记忆的 Agent 图

    图结构：
    
        [load_memory] → [agent_node] → [save_to_memory]
                            |                |
                            ├→ [search_memory] (Agent 的工具调用)
                            |                |
                            └→ [update_profile] (检测到画像变更时)
                                             |
                                        [consolidate]
                                             |
                                           END
    """
    store = store or InMemoryStore()
    checkpointer = checkpointer or MemorySaver()

    builder = StateGraph(MemoryAgentState)

    # 添加记忆节点
    builder.add_node("load_memory", load_memory_node)
    builder.add_node("agent", agent_node_func)
    builder.add_node("save_memory", save_to_memory_node)
    builder.add_node("update_profile", update_profile_node)
    builder.add_node("consolidate", consolidate_memory_node)
    builder.add_node("search_memory", search_memory_node)

    # 连接：先加载记忆，再执行 Agent，最后保存
    builder.set_entry_point("load_memory")
    builder.add_edge("load_memory", "agent")
    
    # Agent 执行完后 → 保存记忆
    builder.add_edge("agent", "save_memory")
    
    # 保存记忆后 → 检查是否需要更新画像
    builder.add_conditional_edges(
        "save_memory",
        lambda s: "update_profile" if s.get("profile_delta") else "consolidate",
        {
            "update_profile": "update_profile",
            "consolidate": "consolidate",
        },
    )
    builder.add_edge("update_profile", "consolidate")
    builder.add_edge("consolidate", END)

    return builder.compile(
        checkpointer=checkpointer,
        store=store,
    )
```

### profiles.py — 基于 Store namespace 的画像系统

```python
"""
基于 LangGraph Store 的画像引擎

使用 Store 的 namespace 实现作用域隔离：
- ("profiles", "{user_id}") → 用户画像
- ("entities", "{entity_type}") → 实体目录

画像更新策略：
1. EMA 平滑：新值以 0.3 权重融入旧值
2. 置信度管理：低于 0.5 暂存为候选，≥0.7 直接更新
3. 去重：Jaccard ≥0.7 视为重复事实
"""

from typing import Optional
from datetime import datetime, date
from langgraph.store.base import BaseStore


class ProfileManager:
    """
    用户画像管理器
    
    使用 LangGraph Store 存储，支持：
    - 多用户隔离
    - 特征 EMA 动态更新
    - 置信度管理
    - 实体识别（基础版）
    """

    def __init__(self, store: BaseStore):
        self.store = store

    async def get_profile(self, user_id: str) -> dict:
        """获取用户完整画像"""
        result = await self.store.get(("profiles", user_id), "profile")
        if result:
            return result.value
        return self._empty_profile(user_id)

    async def update_trait(
        self,
        user_id: str,
        trait: str,
        value,
        confidence: float = 0.5,
    ):
        """更新单个特征（带 EMA 平滑）"""
        profile = await self.get_profile(user_id)
        alpha = 0.3

        if trait in profile["traits"]:
            old = profile["traits"][trait]
            profile["traits"][trait] = {
                "value": value,
                "confidence": round(
                    old["confidence"] * (1 - alpha) + confidence * alpha, 2
                ),
                "history": old.get("history", []) + [
                    {"value": old["value"], "confidence": old["confidence"], "until": datetime.now().isoformat()}
                ],
                "updated_at": datetime.now().isoformat(),
            }
        else:
            profile["traits"][trait] = {
                "value": value,
                "confidence": confidence,
                "first_seen": datetime.now().isoformat(),
                "updated_at": datetime.now().isoformat(),
                "history": [],
            }

        profile["last_seen"] = datetime.now().isoformat()
        await self.store.put(("profiles", user_id), "profile", profile)

    async def add_fact(
        self,
        user_id: str,
        fact: str,
        confidence: float = 0.5,
    ):
        """添加一条用户画像事实（带去重）"""
        profile = await self.get_profile(user_id)

        # Jaccard 去重
        fact_words = set(fact.lower().split())
        for existing in profile["facts"]:
            existing_words = set(existing["fact"].lower().split())
            if fact_words and existing_words:
                jaccard = len(fact_words & existing_words) / len(fact_words | existing_words)
                if jaccard >= 0.7:
                    # 更新已有事实
                    existing["confidence"] = max(existing["confidence"], confidence)
                    existing["last_verified"] = date.today().isoformat()
                    await self.store.put(("profiles", user_id), "profile", profile)
                    return

        # 新事实
        profile["facts"].append({
            "fact": fact,
            "confidence": confidence,
            "created": date.today().isoformat(),
            "last_verified": date.today().isoformat(),
        })

        # 限制事实数量
        profile["facts"] = profile["facts"][-50:]
        await self.store.put(("profiles", user_id), "profile", profile)

    async def get_relevant_profile_context(self, user_id: str) -> str:
        """
        获取格式化的画像上下文，用于注入系统提示

        返回高置信度（≥0.7）的特征和最近验证的事实
        """
        profile = await self.get_profile(user_id)
        parts = []

        # 高置信度特征
        high_conf_traits = {
            k: v for k, v in profile["traits"].items()
            if v.get("confidence", 0) >= 0.7
        }
        if high_conf_traits:
            parts.append("## 用户画像（高置信度）")
            for trait, info in high_conf_traits.items():
                parts.append(f"- {trait}: {info['value']}")

        # 已验证事实
        verified_facts = [
            f for f in profile["facts"]
            if f.get("confidence", 0) >= 0.7
        ]
        if verified_facts:
            parts.append("\n## 已知事实")
            for f in verified_facts[-10:]:  # 最近 10 条
                parts.append(f"- {f['fact']}")

        return "\n".join(parts)

    @staticmethod
    def _empty_profile(user_id: str) -> dict:
        return {
            "user_id": user_id,
            "name": "",
            "role": "",
            "skill_level": "intermediate",
            "traits": {},
            "facts": [],
            "interaction_count": 0,
            "first_seen": datetime.now().isoformat(),
            "last_seen": datetime.now().isoformat(),
        }
```

# 九、三个框架方案对比总结

| 维度 | 方案A：独立实现（OpenClaw 启发） | 方案B：LangGraph 统一（推荐） |
|------|-------------------------------|---------------------------|
| **短期记忆** | 手动管理 SessionContext.turns + 压缩 | StateGraph State + Checkpointer 自动管理 |
| **情节记忆** | 每日 Markdown 文件 + SQLite FTS5 | Store namespace `("sessions", uid, date)` |
| **长期记忆** | MEMORY.md + 时间衰减 | Store namespace `("memories", uid)` + 内置 embedding 搜索 |
| **画像系统** | JSON 文件 + EMA 更新 | Store namespace `("profiles", uid)` |
| **搜索** | FTS5 全文搜索（需升级向量） | Store.search() 内置 embedding 语义搜索 |
| **会话恢复** | 手动 bootstrap 加载 | Checkpointer 自动恢复 + time-travel |
| **多Agent集成** | 需手动编写集成代码 | 原生 Supervisor/Swarm/Subgraph 模式 |
| **与课程衔接** | 需额外学习独立 API | ⭐ 与模块4（LangGraph Workshop）完全一致 |
| **生产升级** | 需自行替换后端 | `InMemoryStore` → `AsyncPostgresStore` 一行切换 |
| **适用阶段** | 理解记忆原理（教学） | 模块4、5、6 统一 + 生产落地 |

### 推荐

**课程教学用方案B（LangGraph 统一）**，理由：
1. 学员在模块4已经学了 LangGraph 的 StateGraph/Node/Edge/Checkpointer，模块5直接复用这些概念
2. Store 的 `put/get/search` API 比文件系统操作更简洁
3. Checkpointer 提供了 OpenClaw 没有的"时间旅行调试"能力
4. 与模块6的多Agent编排（Supervisor/Swarm）无缝衔接
5. 从教学到生产的升级路径一致（换 `InMemoryStore` → `AsyncPostgresStore`）

方案A（文件原生）更适合作为**理论讲解的参考架构**，帮助学员理解"为什么需要分层"，然后方案B展示"如何在 LangGraph 中落地"。

# 十、生产升级路径（LangGraph 版）

## 10.1 从演示到生产


# 十一、关键设计原则总结

| 原则 | LangGraph 落地方式 | OpenClaw 参考 |
|------|-------------------|---------------|
| **文件是图书馆，向量是图书馆员** | Store 是权威数据源，search() 是加速器 | Markdown 是源，SQLite 是索引 |
| **遗忘前先写下来** | save_to_memory_node 在每次 Agent 响应后自动执行 | Pre-compaction Flush |
| **从不删除，只标记过时** | `superseded_by` 字段 + `forget()` 仅标记 | 标记 `historical` |
| **时间衰减确保新鲜度优先** | `_decayed_score()` + recall_count 加权 | 相同公式 |
| **门控写入防止噪声** | consolidate_memory_node 中的评分阈值 | minScore + minRecallCount + minUniqueQueries |
| **优雅降级** | InMemoryStore → SqliteStore → PostgresStore 渐进升级 | 向量不可用时回退 FTS5 |
| **记忆即信任基础设施** | Checkpointer 时间旅行 + Store 命名空间 | 文件可审计 |
