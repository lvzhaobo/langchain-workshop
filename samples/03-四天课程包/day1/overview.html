三条 Agent 通道（统一 SSE）

🔵 DeepSeek 直连

原始 OpenAI 兼容 API + stream:true，平台把对象数据拼进 Prompt，requests 逐行解析 delta 转为 SSE 帧

POST /gateway/chat
通道 ①

🟢 Dify Agent

转发 Dify chat-messages API，response_mode: streaming，逐 chunk 转为统一 SSE 帧

POST /gateway/dify/chat
通道 ②

🦜 LangChain ReAct

纯 while 循环替代 LangGraph StateGraph，Agent 自己决定调哪个工具，工具轨迹以特殊帧输出

POST /agent/single
通道 ③

SSE 协议亮点

data: {"content":"光模块"}
data: {"content":"功率异常"}
data: {"tool":"query_object","content":"\n🔧 [query_object] OBJ-0001 …\n\n"}
data: [DONE]

关键 三通道用同一套帧格式，前端一份 JS 代码消费三条通道。LangChain 通道额外发 tool 帧让学员在前端看到 Agent 的"思考轨迹"。错误帧 data: {"error":"…"} 不崩前端。

关键知识点

  • Agent 不是黑盒：ReAct 通道的 while 循环只有 30 行——LLM 调用 → 有 tool_calls → 执行工具 → 喂回结果 → 继续，这就是全部
  • SSE 是 AI Gateway 的通用语言：三通道走同一套帧格式，深意是「前端不关心 Agent 背后是什么」
  • @tool 形成闭环：Agent 调工具 → 工具回调平台 API → 平台返回数据 → Agent 继续推理。Agent 不直接读文件，和真实运维系统一样走 HTTP
  • 不用 langgraph 也能写 ReAct：引入 langgraph 只为 10 行 StateGraph 太亏——纯 while 循环更直观，学员看得懂每一行
  • 换场景 = 换数据 + 改两处 Prompt：data/objects.json + SYSTEM_PROMPT + Gateway 的 system prompt。页面和接口不用动
