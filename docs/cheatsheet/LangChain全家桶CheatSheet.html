二、LangChain Core — 完整 API

2.1 ChatModel

所有模型调用的统一入口。不管后端是 OpenAI、DeepSeek 还是 Ollama 本地模型，对外都是一个 invoke()。支持批量、流式、容错降级。

from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4.1", temperature=0, streaming=True)

response = llm.invoke("Hello")              # 单条
responses = llm.batch(["q1", "q2", "q3"])  # 批量
for chunk in llm.stream("Hello"): ...       # 流式

# 容错：主模型挂了切备用
model = ChatOpenAI(model="gpt-4.1").with_fallbacks([ChatOpenAI(model="gpt-4o-mini")])

2.2 Prompt Template

把 System Prompt 和用户输入分开管理。支持对话历史占位、Few-shot 示例注入。

from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是{role}，专攻{domain}。"),
    MessagesPlaceholder("history"),    # 对话历史占位
    ("human", "{question}"),
])

2.3 LCEL — 管道语法 |

LangChain 最核心的表达方式：用 | 把组件串成链条。每个组件的输出自动成为下一个组件的输入。支持串行、并行、分支。

# 基础管道
chain = prompt | llm | StrOutputParser()

# 并行：同时跑三条链，结果合并
chain = RunnableParallel(
    summary=summary_prompt | llm | StrOutputParser(),
    keywords=keywords_prompt | llm | StrOutputParser(),
)

# 透传 + 动态赋值
chain = (RunnablePassthrough.assign(extra=lambda x: "value") | prompt | llm | parser)

# 分支：根据条件走不同链
chain = RunnableBranch(
    (lambda x: "math" in x["topic"], math_chain),
    (lambda x: "code" in x["topic"], code_chain),
    general_chain  # 都不匹配走这条
)

2.4 @tool 工具

把一个 Python 函数变成 LLM 能调用的工具。LLM 输出 function call JSON，LangChain 自动解析、执行函数、把结果返回给 LLM。

from langchain_core.tools import tool
from pydantic import BaseModel, Field

# 简单工具
@tool
def query_device(device_id: str) -> str:
    """查询 5G 基站设备详情"""
    return f"{device_id}: 华为 AAU5613, 在线"

# 结构化参数（Pydantic 校验）
class SearchInput(BaseModel):
    query: str = Field(description="搜索关键词")
    max_results: int = Field(default=5)

@tool(args_schema=SearchInput)
def search_kb(query: str, max_results: int = 5) -> str:
    """搜索知识库"""
    return f"找到 {max_results} 条结果"

# 绑定到 LLM
llm_with_tools = llm.bind_tools([query_device, search_kb])

2.5 Structured Output

强制 LLM 返回符合 Pydantic Schema 的结构化 JSON，代码可靠解析。解决"LLM 输出格式不稳定"的问题。

class Diagnosis(BaseModel):
    device_id: str
    root_cause: str
    confidence: float = Field(ge=0.0, le=1.0)

structured_llm = llm.with_structured_output(Diagnosis)
result: Diagnosis = structured_llm.invoke("DEV-0001 光模块告警")

三、LangChain RAG — 完整技术栈

3.1 标准 RAG Pipeline

六步把文档变成能回答问题的知识库：加载文档 → 切割成块 → 每块算向量 → 存入向量库 → 用户问题检索 → LLM 基于检索结果生成回答。

# 1. 加载
docs = TextLoader("knowledge.txt").load()

# 2. 切割（块大小 800 字，重叠 100 避免语义截断）
chunks = RecursiveCharacterTextSplitter(chunk_size=800, chunk_overlap=100).split_documents(docs)

# 3. 向量化（文本 → 1536 维向量）
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

# 4. 存入 FAISS（内存向量索引，百万级毫秒检索）
vectorstore = FAISS.from_documents(chunks, embeddings)

# 5. 检索器（取最相似的 3 个文档块）
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

# 6. RAG Chain：检索 → 填 Prompt → LLM → 输出
rag_chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt | llm | StrOutputParser()
)

四、LangGraph — 完整 API 参考

4.1 StateGraph 三要素 + Reducer

State 是图的共享内存，所有节点通过它通信。Reducer 解决"多个节点写同一个字段怎么合并"的问题——默认覆盖、operator.add 追加、add_messages 消息专用。

class State(TypedDict):
    messages: Annotated[list, add_messages]  # 消息追加+去重
    results:  Annotated[list, operator.add]  # 列表累加
    counter:  Annotated[int, operator.add]   # 数字累加
    flags:    Annotated[bool, operator.or_]  # 任一 True 则 True

4.2 Reducer 全集

Reducer行为State 写法
默认（无）后者覆盖前者name: str
operator.add累加 / 列表拼接Annotated[int, operator.add]
operator.or_任一 True 则 TrueAnnotated[bool, operator.or_]
add_messages消息追加 + 同名去重Annotated[list, add_messages]
自定义任意合并逻辑Annotated[T, custom_func]

4.3 Nodes — 三种签名

# 签 1: 只读 state
def node(state: State): return {"key": val}

# 签 2: state + config（拿 thread_id 等配置）
def node(state: State, config: RunnableConfig):
    tid = config["configurable"]["thread_id"]

# 签 3: state + runtime（读写 Store 长期记忆）
def node(state: State, runtime: Runtime):
    runtime.store.put(["ns"], "key", {"data": "val"})

4.4 Edges 四种方式

固定边：A 之后永远去 B。适合线性流程。
条件边：根据 State 动态决定去 A 还是 B。适合分类、路由。
Command：节点内部决定下一步，写数据+定方向一举完成。适合每个节点自己判断去向。
Send：并行扇出，一个上游变成 N 条下游同时跑。适合批量处理。

# 固定边
builder.add_edge(START, "node_a")

# 条件边
def router(state) -> Literal["a", "b"]: return "a" if state["flag"] else "b"
builder.add_conditional_edges("node", router, ["a", "b"])

# Command — 节点内决定下一步
from langgraph.types import Command
def node(state) -> Command[Literal["a", "b"]]:
    return Command(update={"key": val}, goto="a")

# Send — 并行 Fan-out
from langgraph.types import Send
def dispatcher(state):
    return [Send("worker", {"task": t}) for t in state["tasks"]]

4.5 Checkpoint 持久化

每跑完一个 Superstep（一波可并发的节点），LangGraph 自动把 State 存一份快照。不加 Checkpoint 则 invoke 结束后 State 消失。加了之后可以断点续跑、时间旅行、多会话隔离。

from langgraph.checkpoint.memory import MemorySaver
graph = builder.compile(checkpointer=MemorySaver())

config = {"configurable": {"thread_id": "session-1"}}
graph.invoke(input, config)

state = graph.get_state(config)                     # 读当前状态
for snap in graph.getStateHistory(config): ...      # 遍历历史快照
fork_config = graph.updateState(old_config, {"key": "new"})  # 时间旅行
Checkpointer存储适用
MemorySaver内存 dict测试/Demo
SqliteSaverSQLite 文件本地开发
PostgresSaverPostgreSQL生产环境

4.6 Stream — 7 种模式

invoke() 一口气跑完才出结果，stream() 逐步暴露执行过程。开发调式看 updates，用户端看 messages（打字机效果），排查问题看 debug。

模式输出内容场景
values每步完整 State调式，看全局状态
updates每步节点更新 diff看节点间数据流转
messages逐 token 打字机用户端实时显示
custom自定义事件进度条、状态通知
checkpointscheckpoint 元数据监控存档行为
tasks任务调度信息看 Superstep 内部
debug所有信息汇总深度排查

4.7 HITL 人工审批

Agent 不能自己决定重启核心设备。在高风险操作前插一个审批点：interrupt() 暂停，State 自动存档到 Checkpoint；人做决定后 Command(resume=...) 从暂停点继续。节点函数从 interrupt 那一行接着往下执行。

from langgraph.types import interrupt, Command

def approval_node(state):
    decision = interrupt(f"是否批准: {state['action']}?")
    return {"approved": decision}  # 这行在 resume 之后才执行

graph.invoke(input, config)                  # 跑到 interrupt → 暂停
graph.invoke(Command(resume=True), config)   # 人批准 → 继续

4.8 Subgraph 子图嵌套

把编译好的图当成父图的一个节点。父图把子图当作黑盒——只关心输入输出，不关心里面怎么跑。这是多 Agent 的基础：每个 Worker 可以是一个独立编译的子图，挂到 Supervisor 的编排图中。

child_graph = child_builder.compile()
parent_builder.add_node("child_agent", child_graph)  # 子图作为父图节点

4.9 Long-Term Memory — Store API

Checkpoint 存的是"这次对话跑到哪了"，Store 存的是"跨对话学到的知识"。按命名空间组织记忆，支持语义检索。新会话启动时检索相关记忆注入 System Prompt。

store = InMemoryStore()
graph = builder.compile(store=store)

def my_node(state, runtime: Runtime):
    runtime.store.put(["user_123"], "mem_1", {"data": "..."})
    results = runtime.store.search(["user_123"], query="relevant", limit=3)
