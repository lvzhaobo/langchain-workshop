# Lab 10 · RunnableBranch — LCEL 版的 if/elif/else

> Lab 05 的 Agent 对所有输入一视同仁。本实验给管道加上"分岔路口"：不同告警级别走不同 Prompt。Python if/else 能做的事，LCEL 的管道语法也能做——而且可以扩展为让 LLM 来判断走哪条路。


## 🎯 实验目标

- 理解 `|` 管道符：数据从左往右流
- 用 `RunnableBranch` 实现三级路由
- 知道什么时候用 lambda 做确定性路由，什么时候该让 LLM 来判断


## 🏗️ 原理

```python
# Python if/elif/else:
if severity == "P0":
    return p0_chain(data)
elif severity == "P1":
    return p1_chain(data)
else:
    return default_chain(data)

# 等价的 RunnableBranch:
RunnableBranch(
    (lambda x: x["severity"] == "P0", p0_chain),    # 条件 + 通道
    (lambda x: x["severity"] == "P1", p1_chain),
    default_chain,                                    # 兜底
)
```

每条通道是一条 `prompt | llm | StrOutputParser()` 管道。数据从 `invoke(dict)` 进入，`severity` 字段决定走哪条。


## 📦 运行

```bash
python runnable_branch.py
```

输出：

```
── DEV-0001 (severity=P0) ──
收到 P0 紧急告警…（立即行动方案+升级条件）

── DEV-0002 (severity=P1) ──
P1 重要告警…（排查分析）

── DEV-0003 (severity=NONE) ──
状态正常…（例行检查建议，不超过3条）
```

三台设备、三种通道、三类不同风格的输出——由 `severity` 字段决定，不是代码里写了三个 if 分支。


## 🔑 关键认知：什么时候让 LLM 来路由

当前例子用 `lambda x: x["severity"] == "P0"` ——severity 是已知字段，不需要 LLM。

但很多场景 severity 不是现成的。比如用户自然语言输入：

> "上不了网了！！！" → 紧急
> "最近掉线率有点高，帮看看" → 诊断
> "例行巡检一下" → 常规

Python 正则匹配不出这种区别。这时把 lambda 换成 LLM：

```python
def classify_intent(text: str) -> str:
    return llm.invoke(f"判断意图（emergency/diagnose/routine），只输出单词：{text}")

RunnableBranch(
    (lambda x: classify_intent(x["input"]) == "emergency", emergency_chain),
    (lambda x: classify_intent(x["input"]) == "diagnose",  diagnose_chain),
    routine_chain,
)
```

这是 lab 21（意图识别路由）要做的——先让 LLM 判断意图，再用 RunnableBranch 分叉。

## ⚠️ 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| 所有设备走默认通道 | severity 字段名写错 | 检查 dict key 和 lambda 里取的是否一致 |
| `ImportError: RunnableBranch` | 导入路径不对 | `from langchain_core.runnables import RunnableBranch` |
| 管道报类型错误 | 上一步输出和下一步输入不匹配 | 检查 Prompt 变量名和 dict key 是否对齐 |
