# Lab 09 · Agent 三维选型 — 温度 × 模型 × 行为

> lab 05 的 Agent 用 `temperature=0` 跑通了，但调了温度会怎样？换模型呢？同一个 Agent 面对不同问题，工具调用路径有什么差异？本实验三轮对比，形成「温度 × 模型 × 任务」三维选型判断力。


## 🎯 实验目标

- 同一任务，三档温度（0 / 0.7 / 1.2），看输出风格差异
- 同一 Agent，换不同模型，看效果差异
- 同一 Agent，不同任务复杂度，看工具调用路径差异
- 形成选型判断力：排障默认 temp=0 + DeepSeek


## 📦 标准路径

### 跑起来

```bash
python agent_compare.py
```

### Round 1：温度对比

同一个 DeepSeek + 同一个任务，三档温度各跑一次：

| 温度 | 特点 | 排障场景适用？ |
|------|------|:--:|
| **temp=0** | 精炼、确定性高、每次结果几乎一致 | ✅ 必须用 |
| **temp=0.7** | 平衡、有一定发散、解释偏详细 | 可，但不够稳 |
| **temp=1.2** | 发散、创意性强、长度波动大 | ❌ 别用 |

**核心结论**：排障 Agent 默认 temp=0——先保证准，再追求好。

### Round 2：模型对比

默认用 DeepSeek。如果你有其他模型的 API Key，可以在 `MODEL_CONFIGS` 里追加：

```python
MODEL_CONFIGS = {
    "deepseek-chat": { ... },      # 默认，课程提供 Key
    "qwen-plus": {                 # 可选：通义千问
        "api_key": os.getenv("QWEN_API_KEY", ""),
        "base_url": "https://dashscope.aliyuncs.com/compatible-mode/v1",
    },
    # 更多模型按同样格式追加
}
```

同一任务、同一个 Agent，换模型后对比耗时、回答长度、结论差异。

### Round 3：工具调用路径

同一个 Agent，两个不同复杂度的任务，观察工具调用步骤：

```python
# 简单查询 — 1 步
"DEV-0001 的状态怎么样？"
→ query_device

# 综合诊断 — 4 步
"有哪些设备在告警？把最严重的那台分析一下"
→ list_devices → get_alarms → get_alarms → query_device
```

**关键观察**：不是代码逻辑决定的，是 LLM 读每一步的 Observation 后自行决策。

### 动手改

1. 把 `DEV-0001` 的告警数据删掉，跑同一个问题——Agent 调 `get_alarms` 了吗？
2. 追加一个自己的模型配置，跑 Round 2
3. 写一个需要 5 步以上的复杂任务："列出所有设备，按告警数量排序，分析最严重三台"


## ✅ 验收

- [ ] Round 1 三档温度跑通，能说出每档的特点
- [ ] Round 3 简单查询和综合诊断的工具调用步数不同
- [ ] 能说出"排障场景为什么默认 temp=0"


## ⚠️ 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| 三档温度输出几乎一样 | DeepSeek 对温度不敏感 | 换一个更开放的模型试试 |
| 其他模型报 API Key 错误 | Key 未配置 | 课程只提供 DeepSeek Key，其他模型需自备 |
| 工具调用步数太多 | LLM 过度探索 | 正常，Agent 会逐步缩小范围 |
