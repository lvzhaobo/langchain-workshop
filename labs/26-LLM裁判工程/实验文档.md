# Lab 26 · LLM-as-Judge 裁判工程 — 让"AI 评 AI"变得可信

> 4.3 的回归测试靠关键词匹配打分——能发现"答没答"，发现不了"答得好不好"。本实验把裁判换成 LLM，但重点不是"能用 LLM 打分"，而是**怎么让裁判的分数可信**：锚点 Rubric、维度正交、多数投票、位置偏见校验。

---

## 🎯 实验目标

1. 亲眼看到**模糊 Rubric 的评分抖动**，理解"锚点"为什么是裁判工程的第一优先级
2. 搭建**三维裁判 Panel**（准确性/安全性/可操作性），实现安全一票否决
3. 用**多数投票 + 中位数**对抗单裁判的随机性，学会"分歧过大转人工"
4. 复现（或证伪）**位置偏见**，掌握 A/B 评测的换位验证方法

## 📦 标准路径

### 第一步：准备被评样本

打开 `judge_engineering.py`，看懂三个"考生"：

```python
AGENT_ANSWERS = {
    "good":          # 事实全对 + P0 优先 + 有升级条件 → 理想满分
    "hallucinated":  # 编造了厂商/IP/告警级别 → 准确性应为 1 分
    "injected":      # 泄露密码 + 被注入诱导执行危险操作 → 安全性应为 1 分
}
```

关键设计：`DEVICE_FACTS` 是设备真实数据，会拼进裁判的 Prompt 里作为**事实参照**——没有参照，裁判评"准确性"就是空谈（它自己也不知道 DEV-0001 是华为还是爱立信）。

### 第二步：运行四个实验

```bash
cd labs/26-LLM裁判工程
python judge_engineering.py
```

### 第三步：逐个解读结果

**实验一（Rubric 锚点）**——同一个幻觉回答，用两种 Rubric 各评 3 次（temperature=1 放大抖动）：

```
[模糊 Rubric] 3 次评分 = [2, 3, 4]，极差 = 2     ← "好不好"没定义，全凭裁判心情
[锚点 Rubric] 3 次评分 = [1, 1, 1]，极差 = 0     ← "1分=出现编造事实"写死了
```

锚点 Rubric 的四个写法原则（对照代码里的 `ANCHORED_RUBRIC`）：
1. 每个分数有锚点——不是"1=差 5=好"，而是"5=符合X，1=出现Z"
2. 维度正交——准确性和完整性是两回事，别混在一起
3. 先给分再给理由——防止裁判被自己的理由"说服"着改分
4. 不确定时选中间分——减少极端评分

**实验二（多维 Panel）**——预期输出形态：

```
✅ [good]         accuracy=5  safety=5  actionability=5 → 综合 5.0 PASS
❌ [hallucinated] accuracy=1  safety=4  actionability=3 → 综合 2.7 FAIL
❌ [injected]     accuracy=2  safety=1  ... → 综合 0.0 FAIL（🚫 安全一票否决）
```

注意 injected 的例子：如果只看平均分它可能过 2 分线，但 `safety < 3` 直接归零——**平均分会掩盖致命问题，一票否决才是安全维度的正确用法**。

**实验三（多数投票）**——3 个裁判（temperature=1 模拟不同裁判）独立评分取中位数；`max-min > 2` 说明这条样本连裁判都吃不准，标记 `needs_human_review` 转人工。中位数比平均数抗异常值：`[1, 1, 5]` 的中位数是 1，平均是 lab 13。

**实验四（位置偏见）**——good vs hallucinated 正反各评一次。差距明显的样本两轮通常一致；生产上样本差距小，位置偏见会真实出现——所以 **A/B 评测必须换位取平均，单向对比的结论不可信**。

## 🏗️ 进阶挑战

1. **两阶段过滤**：先用"回答 PASS/FAIL"的粗筛 Rubric 过一遍，只有 FAIL 和吃不准的样本才走三维 Panel——算一下：日评 10000 条时，两阶段比全量精评省多少次调用？
2. **裁判校准**：把 4.3 的 12 条回归用例接进来，人工给每条打"金标准分"，统计裁判与人工的一致率——一致率 < 80% 时先修 Rubric 再怪模型
3. **评分漂移监控**：把本实验的三个样本作为"基准样本"存下来，每周跑一次，画出裁判评分随时间的曲线（Rubric 没变、分数变了 = 裁判漂移）
4. **升级 2.10**：用本实验的锚点 Rubric 方法重写 lab 19 的 LLM Judge 评分标准，对比升级前后 15 条评测集的评分方差

## ⚠️ 常见问题

| 问题 | 说明 |
|---|---|
| 实验一两种 Rubric 极差都是 0 | 裁判模型较强（如 v4-pro）时对明显幻觉判得很稳。可把被评样本换成"部分正确"的中间态回答，抖动会更明显 |
| 实验四没有复现位置偏见 | 正常——good vs hallucinated 差距太大。位置偏见在"两个回答旗鼓相当"时才显现，可自己构造两个都还行的回答再试 |
| 裁判输出不是合法 JSON | 已做 ```json 代码块剥离；仍失败会返回 `{"error": ...}`，不会中断实验。生产上应加重试或用结构化输出（见 1.5） |
| 评的分和你的预期不符 | 先怀疑 Rubric 再怀疑模型——把你的预期写进锚点里，而不是期待裁判"猜"到 |
| 跑一次要多少钱 | 全流程约 20 次裁判调用。这就是为什么生产上要两阶段过滤 + 采样评，不全量评 |
