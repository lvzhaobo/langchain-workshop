Trace / Span 数据模型

一次请求 = 一条 Trace；每个子步骤 = 一个 Span

两个概念，一条规则

  • Trace——一次完整的用户请求。有 trace_id、名字、输入、总耗时、总 token
  • Span——请求内部的一个可计时片段。有 span_id、类型（agent / tool / llm）、耗时、token
  • 规则——Span 可以嵌套。Agent 内部调工具，工具的 Span 就是 Agent Span 的儿子

三种 span_type 的意义

本实验用 agent / tool / llm 三类。分类不是为了好看——生产上要按类型聚合：llm 类看 token 和成本，tool 类看外部依赖的稳定性，agent 类看业务编排的整体延迟。混在一起统计就失去了意义。

手工埋点的三行范式

start_span → 执行业务 → end_span。end_span 时才知道耗时和 token，所以输出和用量都在结束时补录。这个成对调用的纪律一旦破了（漏一次 end_span），整条 Trace 的结构就错。

为什么先手写再上 Langfuse

Langfuse 的 CallbackHandler 一行就自动采集，但学员不会知道它在背后做了什么。先手写 LocalTracer，把 span 栈、父子关系、耗时口径这些坑踩一遍，再看自动方案才知道它替你解决了什么。

STK

核心考点：span 必须用栈，不能用单变量

本实验修复的真实 bug — 200 token 凭空蒸发

错误实现：一个 _current_span

最直觉的写法是拿一个变量记「当前 span」。单层调用完全正常，一旦嵌套就崩：start_span("diagnoser") 之后紧接 start_span("faiss_search")，第二次赋值把 diagnoser 整个覆盖掉——它从此不存在了。

崩坏的连锁反应

  • 第一次 end_span 关掉的是 faiss_search，_current_span 变成 None
  • 第二次 end_span 发现 None，直接 return——本该记给 diagnoser 的 200 token 蒸发
  • diagnoser 这个 span 从未入列，报告里看不到它，也不知道它慢
  • 总 token 从应有的 650 变成 450，而且没有任何报错
这类 bug 为什么最危险

它不抛异常、不崩程序，只是安静地少统计。你拿着「总耗时 450 token」的报告去做成本核算，误差 30% 却毫不知情。可观测系统自己出错，是最难发现的一类错——因为你本来就是靠它来发现别的错。

 修复后：span 栈 + 父子关系
def __init__(self):
    # span 必须用栈而不是单个变量：嵌套调用（agent 里套
    # tool）时，单变量会被子 span 覆盖，父 span 永久丢失
    self._span_stack: List[Dict] = []

def start_span(self, name, span_type="agent") -> str:
    parent = self._span_stack[-1] if self._span_stack else None
    self._span_stack.append({
        "span_id": sid, "name": name, "type": span_type,
        "parent_span_id": parent["span_id"] if parent else None,
        "depth": len(self._span_stack),
        "start": time.time(),
    })
    return sid

def end_span(self, output=None, tokens=0):
    if not self._span_stack: return
    span = self._span_stack.pop()          # 后进先出，配对准确

统计口径与树形可视化

两个容易算错的地方

坑一：总耗时不能把所有 span 加起来

faiss_search 的 155ms 已经包含在 diagnoser 的 358ms 里了。全部相加会重复计算，得出比真实墙钟时间更长的总耗时。正确口径是只累加顶层 span（parent_span_id is None）。

坑二：token 反过来，必须全加

耗时是区间包含关系，token 是独立消耗——diagnoser 自己烧了 200，faiss_search 另外烧了 80，两者不重叠。所以 total_tokens 在每次 end_span 时无条件累加，和耗时的处理正好相反。这个不对称是最容易搞混的点。

坑三：入列顺序不是显示顺序

因为子 span 先结束，spans 列表里 faiss_search 排在 diagnoser 前面。直接按列表顺序打印加缩进，faiss_search 就会显示在 detector 底下——挂错父亲。必须按 parent_span_id 重建树序再输出。

 耗时：只累加顶层
def end_trace(self) -> Dict:
    # 只累加顶层 span 的耗时，子 span 已含在父区间内，
    # 否则重复计算
    total_ms = sum(s.get("elapsed_ms", 0)
                   for s in trace["spans"]
                   if s.get("parent_span_id") is None)
 显示：按父子关系重建树序
def _tree_order(spans: List[Dict]):
    """把按结束时间入列的 spans 重排为树形顺序：
    父在前，紧跟其子。返回 (span, is_last)。"""
    by_parent: Dict = {}
    for s in spans:
        by_parent.setdefault(s.get("parent_span_id"), []).append(s)

    out = []
    def walk(parent_id):
        children = by_parent.get(parent_id, [])
        for i, s in enumerate(children):
            out.append((s, i == len(children) - 1))
            walk(s["span_id"])          # 深度优先
    walk(None)
    return out
柱状图的分母也要小心

_bar() 用 span耗时 / trace总耗时 算占比。既然总耗时只算顶层，子 span 的柱长表达的是「占整次请求的比例」，而不是「占父 span 的比例」——读图时要清楚分母是什么。

内网可用需要海外网络docker compose up -d 即可
结论运营商场景选 Langfuse——排障数据不出机房，开源无调用上限。

SmartTracer：装不装都能跑

课堂上不能假设所有人都起了 Docker。trace_langfuse.py 用一个 SmartTracer 做三级降级——密钥没配 → langfuse 没装 → 连接失败，任一情况都自动回落到 LocalTracer，只打印提示不报错。同一份代码，配了密钥的人看 Web 面板，没配的人看控制台。

判断密钥是否为占位符

默认值就是 "pk-lf-..." 这种占位串，所以启用条件不是「环境变量存在」而是「值不等于占位符」。这个细节决定了没配密钥的人不会拿着假密钥去连接然后超时卡住。

接入方式：Callback 一行

Langfuse 的 CallbackHandler 挂进 config={"callbacks":[...]} 后，LangChain 内部的每次 LLM 调用、Tool 调用、Agent 决策都会自动上报——不需要手写 start_span / end_span。它自动帮你处理的正是本实验手动踩过的 span 栈和父子关系。

别忘了 flush()

Langfuse 是异步批量上报。短脚本跑完就退出，缓冲区里的数据来不及发送就丢了。所以脚本结尾必须 tracer.flush()——本地模式下它是空操作，无副作用。

坑位表

现象原因与处理
某个 span 不见了用单变量存 current span，嵌套时被子 span 覆盖。必须用栈。
token 总数偏小同上——父 span 的 end_span 因为栈空提前 return，token 没累加。
总耗时虚高把子 span 耗时也加进去了。只累加 parent_span_id is None 的。
子 span 挂错父亲直接按 spans 列表顺序打印。子 span 先结束先入列，必须走 _tree_order()。
漏调 end_span栈不平衡，后续 span 全部挂在这个未关闭的 span 下。埋点必须严格成对。
Langfuse 面板没数据脚本退出太快，异步上报未完成。结尾加 tracer.flush()。
连接 localhost:3000 超时Docker 没起，或用了占位密钥。SmartTracer 会自动降级，看提示行确认当前 mode。
以为要装 langchaintrace_demo.py 只用标准库。装了 langchain 会额外启用 LangChainTracer 回调类，不装也能跑。
