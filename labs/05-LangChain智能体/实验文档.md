# Lab 05 · LangChain 智能体 —— 从 @tool 到 ReAct

> 用 LangChain 写出第一个代码级 Agent：定义工具、创建 Agent、让 LLM 自己决定调哪个工具。


## 📚 LangChain Agent 类型速览

LangChain 提供了几种 Agent，核心区别在于**怎么决定调哪个工具**：

| Agent 类型 | 创建函数 | 机制 | 适用场景 |
|-----------|---------|------|----------|
| **ReAct** | `create_agent` | LLM 思考→行动→观察 循环 | 教学、调试 |
| **Tool Calling** | `create_agent` + function_call | 结构化 function_call | 生产、解析精确 |

LangChain 1.x 统一为 `create_agent`，系统自动根据模型能力选择最优策略。`@tool` 从 `langchain_core.tools` 导入。


## 🎯 实验目标

- 用 `@tool` 定义三个自包含工具（不依赖外部 API）
- 用 `create_agent` 创建第一个 Agent
- 观察 LLM 如何自行决定调哪个工具、调几次


## 📦 标准路径

### 第一步：装依赖

```bash
pip install langchain langchain-openai
```

### 第二步：定义工具 + 创建 Agent

新建 `agent_langchain.py`，三个工具用硬编码数据——不依赖 1.3 平台，专注看 Agent 循环：

```python
import os
from dotenv import load_dotenv
load_dotenv()

from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langchain.agents import create_agent


@tool
def query_device(device_id: str) -> str:
    """查询设备详情。参数 device_id 如 DEV-0001"""
    devices = {
        "DEV-0001": "华为 AAU5613 | 宏站 | 北京朝阳 | 告警中",
        "DEV-0002": "中兴 AAU8851 | 宏站 | 广州天河 | 运行中",
        "DEV-0003": "爱立信 AIR 6488 | 宏站 | 深圳南山 | 告警中",
    }
    return devices.get(device_id, f"设备 {device_id} 不存在")


@tool
def get_alarms(device_id: str) -> str:
    """查询设备告警。参数 device_id 如 DEV-0001"""
    alarms = {
        "DEV-0001": "[P0] 基站退服 — SCTP链路中断\n[P1] 性能劣化",
        "DEV-0003": "[P2] 传输中断",
    }
    return alarms.get(device_id, "无告警")


@tool
def list_devices(status: str = "") -> str:
    """列出设备清单。参数 status 可选 running/alarm/maintenance"""
    all_devices = [
        ("DEV-0001", "AAU5613", "alarm"),
        ("DEV-0002", "AAU8851", "running"),
        ("DEV-0003", "AIR 6488", "alarm"),
        ("DEV-0004", "BBU5900", "running"),
        ("DEV-0005", "RRU8862", "maintenance"),
    ]
    filtered = [d for d in all_devices if not status or d[2] == status]
    return "\n".join([f"{d[0]} | {d[1]} | {d[2]}" for d in filtered])


def make_agent():
    llm = ChatOpenAI(
        model="deepseek-chat",
        temperature=0,
        api_key=os.getenv("AGENT_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    )
    return create_agent(
        llm,
        [query_device, get_alarms, list_devices],
        system_prompt="你是排障助手。用工具查询后给出分析结论。",
    )


if __name__ == "__main__":
    agent = make_agent()

    # 测试 1：查单台 → Agent 串行调 query_device + get_alarms
    print("=" * 50)
    print("测试 1：查单台设备")
    print("=" * 50)
    result = agent.invoke({"messages": [("user", "DEV-0001 的状态怎么样？有哪些告警？")]})
    print(result["messages"][-1].content)

    # 测试 2：查全部 → Agent 先 list_devices 再逐个分析
    print("\n" + "=" * 50)
    print("测试 2：找出告警设备并分析最严重的")
    print("=" * 50)
    result = agent.invoke({"messages": [("user", "有哪些设备在告警？把最严重的那台分析一下")]})
    print(result["messages"][-1].content)
```

### 第三步：跑起来，看终端

```bash
source ../../.venv/bin/activate
python agent_langchain.py
```

**测试 1 观察**：Agent 先调 `query_device("DEV-0001")`，看到"告警中"后自动调 `get_alarms("DEV-0001")`——两次调用是 LLM 自己决定的。

**测试 2 观察**：Agent 先调 `list_devices()` 拿到全部设备，自己对比发现 DEV-0001 和 DEV-0003 告警中，选中 DEV-0001 分析——对比逻辑是 LLM 做的，不是代码写的。

### 第四步：改数据，看行为变化

把 `DEV-0001` 的数据从 `"告警中"` 改成 `"运行中"`，告警数据也删掉。再跑测试 1——Agent 查到状态正常、无告警，直接给出"设备运行正常"的结论，不会再调 `get_alarms`。

**这不是 if/else 代码逻辑，是 LLM 读 Observation 后自己做的决策。** 这就是 Agent 和普通程序的核心区别。


## ✅ 验收

- [ ] 测试 1 和测试 2 都能跑通，输出包含查询结果和分析结论
- [ ] 能看到不同输入触发不同的工具调用顺序
- [ ] 改数据后运行正常状态的设备，Agent 不调 `get_alarms`


## ⚠️ 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| `ModuleNotFoundError: langchain` | 没装 | 先建 `.venv` → `pip install langchain langchain-openai` |
| `ImportError: cannot import name 'tool'` | 旧版代码 | 用 `from langchain_core.tools import tool` |
| 工具调了结果不对 | 数据写错了 | 检查字典里的 key 是否和工具参数传的一致 |
