# Lab 04 · Dify Agent — 创建 5G 基站排障助手

> 在 Dify 平台创建一个排障 Agent 应用，发布为 API。后续 lab 会把平台页面接入这个 Agent，实现页面内对话。

---

## 🎯 实验目标

- 在 Dify 平台创建一个 5G 基站排障 Agent 应用
- 配置 System Prompt，让 Agent 具备排障专家角色
- 发布为 API，获得调用地址和 API Key
- 测试：输入故障描述，Agent 给出排障建议

## 📦 标准路径

### 1. 登录 Dify

打开讲师提供的 Dify 地址，用分配的账号登录。

### 2. 创建应用

- 工作室 → 创建应用 → 选择「Chatflow」
- 应用名称：`5G基站排障助手`
- 应用描述：`协助运维人员诊断 5G 基站设备故障，提供排障建议`

### 3. 编排 Chatflow

在画布上拖入以下节点并连线：

```
[开始] → [LLM] → [结束]
```

**LLM 节点配置**：

- 模型：选择讲师指定的模型（DeepSeek-Chat / GPT-4o-mini）
- System Prompt：

```text
你是 5G 基站智能排障助手。你负责协助运维人员诊断设备故障。

## 你的能力
- 根据设备型号和故障现象，推断可能的根因
- 给出结构化的排查步骤（逐条列出）
- 区分告警级别（P0 紧急 / P1 严重 / P2 一般 / P3 提醒），优先处理高优先级

## 你用的设备信息
当前平台管理的设备情况：
- 50 台 5G 基站设备（华为 AAU5613/AAU5639/BBU5900、中兴 AAU8851/ITBBU8600、爱立信 AIR 6488/Baseband 6630、诺基亚 AirScale 64T64R 等型号）
- 分布在 28 个城市站点
- 告警类型包括：基站退服、性能劣化、传输中断、配置错误、硬件故障

## 回答要求
- 给出诊断时，分步骤列出排查操作
- 如果用户提到了具体设备 ID（如 DEV-0001），针对该设备型号给出建议
- 不确定时说明"建议进一步检查 XXX"
- 不要编造不存在的命令或操作
```

- User Prompt：`{{sys.query}}`

### 4. 测试

在右侧预览面板测试：

| 测试输入 | 预期 Agent 行为 |
|---------|---------------|
| "AAU5613 设备退服了怎么排查？" | 给出针对 AAU5613 的排查步骤 |
| "华为设备常见硬件故障有哪些？" | 列出常见故障类型和处理建议 |
| "P0 级别告警的标准处置流程是什么？" | 给出标准流程步骤 |

### 5. 发布

- 点击右上角「发布」
- 发布成功后，进入「访问 API」页面
- 记录以下信息：

| 项目 | 你的值 |
|------|--------|
| API URL | |
| API Key | |

### 6. curl 验证

```bash
curl -X POST "你的API_URL" \
  -H "Authorization: Bearer 你的API_Key" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "AAU5613 SCTP 链路中断怎么排查？",
    "response_mode": "blocking",
    "user": "test-user"
  }'
```

确认能收到 Agent 的 JSON 响应。
