# Lab 07 · Tool 设计规范 —— 好工具和坏工具的天壤之别

> lab 05 你用 `@tool` 写出了第一个工具，Agent 跑起来了。但你会发现：有时候 Agent 就是选不对工具，传的参数也不对。问题大概率不在模型——在你的 docstring。本实验用"坏工具 vs 好工具"对照实验，量化 docstring 对调用准确率的影响。


## 🎯 实验目标

- 理解好的 Tool docstring 的三个要素：参数说明、返回值格式、使用场景
- 亲手对比"坏工具"vs"好工具"——同一个 LLM、同一个问题，唯一变量是 docstring
- 掌握参数设计原则（必填/可选、默认值、命名规范）
- 掌握返回值设计原则（JSON > Markdown > 自由文本）


## 🏗️ 实验设计

```
同一个 LLM（temperature=0，排除随机性）
        │
        ├── 坏工具组 ──→ 同一个问题，选错工具 / 传错参数
        │
        └── 好工具组 ──→ 同一个问题，准确选择和传参
```


## 📦 标准路径

### 第一步：读代码

打开 `tool_design.py`，先看六组工具对比：

| 坏工具 | 好工具 | 差距在哪 |
|--------|--------|----------|
| `bad_query_device(device)` | `good_query_device(device_id)` | 参数命名 + docstring 信息量 |
| `bad_query_alarms(device)` | `good_query_alarms(device_id, severity="")` | 可选参数 + 返回格式说明 |
| `bad_recommend_action(device)` | `good_recommend_action(device_id, diagnosis)` | 返回 JSON vs 自然语言 |

### 第二步：跑对比

```bash
python tool_design.py          # 完整版，逐步讲解
python tool_design.py --quick  # 快速版，只跑对比结果
```

观察输出：坏工具组 LLM 调了哪个工具？传了什么参数？好工具组呢？

### 第三步：改造你在 lab 05 写的 @tool

回到 Lab 05 的 `agent_langchain.py`，按三条铁律改造你的三个工具：

**① docstring 写清三件套**：
- 参数：类型、格式、示例值
- 返回值：格式（纯文本/JSON/表格）、字段含义
- 使用场景：用户问什么时应该调这个工具

**② 参数有区分度**：
- `device_id` 不是 `device`
- `alarm_severity` 不是 `level`
- 可选参数给默认值

**③ 返回值可消费**：
- JSON 能直接渲染卡片
- Markdown 表格次之
- 自由文本最不可靠


## ✅ 验收

python tool_design.py --quick

观察坏工具组 vs 好工具组的工具选择和参数差异。
