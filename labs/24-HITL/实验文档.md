## 🏗️ 审批点放在哪

```
detector → diagnoser → decider
                           │
                    risk_level?
                      │
              high    │    medium/low
                │     │        │
         ┌──────▼──┐  │   ┌────▼────┐
         │ ⏸️ HITL  │  │   │ executor│  直接执行，不暂停
         │ interrupt│  │   └─────────┘
         └────┬─────┘  │
              │        │
         Command(resume)
              │
         ┌────▼────┐
         │ executor│
         └─────────┘
```

审批点的位置有讲究：放在 decider 之后、executor 之前——**"已经知道要做什么了，但还没做"**——这是最适合人工介入的时刻。

## 📦 标准路径

### 第一步：理解 interrupt 机制

LangGraph 的 `interrupt()` 不是异常——它是将 Graph 状态序列化到 MemorySaver，然后返回给调用方。调用方检查状态、展示审批界面、等人操作、然后用 `Command(resume=...)` 恢复。

```python
def human_approval_node(state):
    # interrupt() 在这里暂停整个 Graph
    approval = interrupt({
        "type": "hitl_approval",
        "device_id": state["device_id"],
        "risk_level": state["risk_level"],
        "diagnosis_summary": state["decide_result"][:300],
    })

    # 下面这行只有在 Command(resume=...) 被调用后才执行
    if approval.get("approved"):
        return {**state, "approval_status": "approved"}
    return {**state, "approval_status": "rejected"}
```

### 第二步：终端 input 模式 —— 零依赖

```bash
python hitl_workflow.py
```

Agent 跑到 decider，发现 risk_level=high → `interrupt()` 暂停 → 终端打印审批信息 → 你输入 y/n → `Command(resume=...)` 恢复。

这是最简形态——不需要 Flask、不需要前端、不需要飞书。学员先在这里理解 interrupt/resume 的机制。

}

### 第四步：飞书卡片通知 —— 讲师演示

**学员不需要做这一步。** 讲师在演示时使用。

前提：`lab-07/api/feishu-server.py` 已在 `localhost:3456` 运行。

流水线触发审批后，`_notify_feishu()` 向飞书群发送一张卡片消息——卡片的两个按钮是 **URL 链接**，指向 Web 审批页面：

```
┌──────────────────────────────────────┐
│ ⏸️ 人工审批 · 5G基站排障             │
│                                      │
│ 设备：DEV-0001  |  风险等级：high     │
│ 诊断：SCTP 端点配置不匹配…            │
│                                      │
│ [✅ 通过审批]   [❌ 驳回审批]          │
│  → 打开浏览器   → 打开浏览器           │
│    审批页面       审批页面             │
└──────────────────────────────────────┘
```

讲师在飞书 App 中点击按钮 → 自动打开手机/电脑浏览器 → Web 审批页面 → 点击通过/驳回 → Web 服务唤醒流水线。

**为什么用 URL 链接而非卡片回调**：飞书卡片按钮的回调需要飞书服务器 POST 到公网可达的 bot 事件地址，本地开发环境无法接收。URL 链接模式不需要公网——按钮直接打开 `localhost:8100` 的页面（讲师在自己电脑上演示时可用）。

## 🏗️ 进阶挑战

### 1. 审批超时自动降级

当前 HITL 无限等。加一个超时机制：5 分钟没审批 → 自动降级为"驳回"并发送催办通知。

### 2. 审批意见反馈给 Agent

审批人驳回时附带审批意见（如"需补充传输链路光功率数据"），这个意见传回 `diagnoser_node`——Agent 根据审批意见重新诊断。

### 3. 多级审批

当前只有一级审批。改为两级：P0 告警需两级审批（一线运维 → 二线专家），P1 告警只需一级。用两个 HITL 节点串联。

## ⚠️ 常见问题

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| `interrupt()` 后无法恢复 | 没有传 `checkpointer` | `graph.compile(checkpointer=MemorySaver())` |
| `Command(resume=...)` 报错 | thread_id 不匹配 | 确保 resume 使用与 interrupt 相同的 `config` |
| 飞书卡片发送失败 | `feishu-server.py` 未启动或 open_id 错误 | 确认 `localhost:3456/api/status` 正常；飞书通知不影响主流程 |
